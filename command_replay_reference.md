# Command replay reference

Base: `923cfca44df82422a1b9d45b02203dfee6baa048`

Ported from: `b3730812bf482f979a86e77115b92881b564c79d`

This branch is a reference for the remaining conversion on main. The base's
buffer copy, image copy, pipeline barrier, secondary import, and Begin/Next/End
render-pass implementation are retained.

## Remaining command support

- `BufferAccessCommand`: fill/update buffer, copy query results, buffer markers.
- `ImageTransferCommand`: buffer/image transfers, blits, resolves, image clears.
- `ShaderAccessCommand`: descriptor accesses for dispatch, draw, and trace commands,
  with their other resource accesses appended through `ResourceAccessCommand`.
- `ResourceAccessCommand`: vertex/index, indirect/count-buffer,
  attachment, video, acceleration-structure, and shader-binding-table accesses.
- `EventCommand`: set/reset/wait operations, including synchronization2.
- Dynamic rendering records its load, resolve, and store accesses through
  `ResourceAccessCommand`.

The command definitions and storage are in `layers/sync/sync_command.h`.
Their validation, application, and reconstruction are in `sync_command.cpp`.
Resource collection is in `sync_command_buffer.cpp` and `sync_validation.cpp`.

## Decisions carried forward from main

- Keep main's three render-pass command types, tag counts, `Apply` signatures,
  scratch validation contexts, and `std::optional` replay render-pass context.
- Keep the queue IDs already carried by subpass barriers and async references.
- Apply every stored command during replay, including after a reported hazard.
- Use main's shared `BaseObjectList` and `AddReplayInfo` reporting helpers.
  New reporters pass the whole hazard to `AddReplayInfo`, including its handling
  of accesses generated by the same command that have an invalid prior tag.
- Preserve default-mode error output. No settings defaults are changed.

## Adaptations required by this port

Stored draw and clear-attachment accesses contain local render-pass instance
IDs. Their reconstructed command now applies the same instance offset as
`CommandReplayContext::BeginRenderPass` in both validation and application.
The stored accesses remain unchanged, so repeated submissions cannot accumulate
the offset. Dynamic-rendering attachment accesses receive the same treatment.

Event validation uses destination tags to compare against the event's captured
scope. `ReplayCommands` passes the rebased tag to event validation, while other
commands retain local replay tags for recorded-command reporting.

Fence, semaphore, and presentation processing use `IsSubmitTimeProcessingEnabled`
where needed so full validation also works with legacy submit validation disabled.
The deferred legacy render-pass external-dependency queue-ID fix is not included.

## Prototype choices still open

Commands borrow spans, matching main's existing commands. Validation and recording
callers own temporary vectors. Standalone collectors return vectors by value, while
collectors that accumulate accesses take a vector by reference. Descriptor collection
returns the pipeline and separate buffer/image vectors together. Commands are
constructed after collection and do not outlive the vectors. Record helpers register handles before
constructing the command.
During replay, spans point directly into `CommandData` without allocating arrays.
Event commands likewise borrow the caller's event and barrier arrays.

The generic commands' remaining per-access metadata is a prototype choice, not a
prerequisite for continuing the conversion on main.

Descriptor accesses now have dedicated buffer and image-view entries, without the
generic reporting strings, optional metadata, or unrelated flags. Their resource
pointers remain directly usable in persistent storage. Buffer and image-view accesses
occupy separate arrays in `CommandData`, and replay constructs two spans without
allocating or decoding an access array. Validation and application process buffers
before images, preserving order within each array. There is no mixed-order reference
list or per-access variant discriminator. Descriptor pipeline ownership
is retained once rather than per descriptor access, and each referenced descriptor
set once per stored command. Non-descriptor accesses keep their existing ownership.
Other accesses remain in their existing order after the descriptor accesses.

Measured with clang-cl targeting Windows x64 and the MSVC Debug runtime, buffer
descriptor entries occupy 80 bytes and image-view entries 104 bytes, versus 112 bytes
for either entry in the previous variant array. Shader command Storage grows from
24 to 32 bytes for the second range, while CommandEntry remains 120 bytes. Mixed
commands now collect into two temporary vectors rather than one. These are layout
measurements, not performance measurements.

Shader accesses retain the existing heuristic and capture the resource accesses
visible during recording. This port does not introduce submit-time descriptor
re-resolution or extend update-after-bind coverage.

`HasAllCommands` and the existing incomplete-stream fallback remain. Passing the
suite does not imply that hardware-dependent skipped paths or every secondary
inheritance case have been exercised.
